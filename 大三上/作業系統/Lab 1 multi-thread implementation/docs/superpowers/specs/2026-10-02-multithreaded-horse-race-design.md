# Java 多執行緒賽馬程式設計規格

## 目標

使用純 JDK 與 Swing 製作可重複遊玩的賽馬動畫。每匹馬由獨立執行緒推進，每場比賽的速度與體力重新隨機；第一匹馬抵達終點後，尚未完賽的馬依體力自動獲得有限次的 20% 加速。GUI 必須安全、流暢地顯示比賽過程與完整排名。

## 技術與範圍

- Java 與 JDK 內建 Swing／Java2D，不使用 Maven、第三方函式庫或外部圖片。
- 以命令列 `javac` 編譯，以 `java` 執行。
- GUI 可設定 2–10 匹馬，預設 5 匹。
- 同一視窗可連續進行多場比賽，每場重新產生基礎速度與體力。
- 馬匹以 Java2D 圖形及文字標籤呈現，避免字型或圖片資源缺失。

## 使用者介面

採用「下方名次列」配置，讓跑道取得最大水平空間。

1. 上方工具列包含馬匹數量 `JSpinner`、開始／再賽一場按鈕及場次資訊。
2. 中央 `RacePanel` 由上至下繪製跑道。每條跑道顯示馬匹編號、馬匹圖形、剩餘體力及加速狀態。
3. 跑道右端顯示醒目的終點線。
4. 下方依完賽順序橫向加入名次，例如「1. 3 號馬、2. 1 號馬」。
5. 最底部狀態列顯示等待、比賽中、首匹完賽與全數完賽等訊息。

比賽進行期間停用馬匹數量與開始按鈕；全部完賽後重新啟用，按鈕文字改為「再賽一場」。

## 架構與元件

### `Main`

使用 `SwingUtilities.invokeLater` 在 Event Dispatch Thread（EDT）建立並顯示 `RaceFrame`。

### `RaceFrame`

組合控制列、`RacePanel`、名次列與狀態列。接收控制器事件，並確保所有 Swing 元件更新都在 EDT 發生。視窗關閉時要求控制器停止尚未完成的執行緒。

### `RacePanel`

根據不可變的馬匹狀態快照繪製跑道、馬匹、終點線、體力與加速標記。它不負責執行緒控制或排名規則。

### `Horse`

每個 `Horse` 實作 `Runnable`，擁有獨立編號、隨機基礎速度、位置、1–3 點體力與停止狀態。執行迴圈只更新自己的狀態，抵達終點時呼叫控制器提供的完賽回呼。

### `RaceController`

建立一馬一執行緒、管理生命週期、發布狀態快照、同步記錄排名，並以一次性旗標保證「首匹完賽」事件只觸發一次。它不直接操作 Swing 元件，而是透過監聽介面傳遞狀態與賽事事件。

## 賽事資料流程

1. 使用者選擇馬匹數量並按開始。
2. `RaceFrame` 要求 `RaceController` 建立新賽事。
3. 控制器為每匹馬隨機產生基礎速度與 1–3 點體力，建立並啟動獨立 `Thread`。
4. 每匹馬在自己的迴圈中休眠短暫時間，再以浮點位置累加移動距離。使用浮點位置可精確呈現 `1.2×`，避免整數四捨五入令 20% 加速失效。
5. Swing `Timer` 約每 33 毫秒取得一次狀態快照，更新 `RacePanel`，達到約 30 FPS。
6. 馬匹抵達終點時，控制器以同步方法加入排名；同一匹馬只能加入一次。
7. 第一個完賽回呼原子地啟用加速模式。仍在比賽的馬立即開始消耗自己的體力。
8. 全部馬匹完賽後，控制器發布最終排名，停止更新並通知 GUI 恢復控制元件。

## 隨機速度與加速規則

- 每匹馬的基礎移動速度在每場開始時獨立隨機，且控制器會避免同一場所有馬得到完全相同速度。
- 動畫迴圈可加入小幅隨機抖動，使過程自然，但不得令位置倒退。
- 首匹完賽前，所有馬只使用基礎速度。
- 首匹完賽後，每匹尚未完成的馬自動進入加速：每點體力提供 1 秒的 `1.2×` 速度。
- 每開始一段 1 秒加速便扣除 1 點體力；體力用完或馬匹完賽後停止加速。
- 已完賽的馬不消耗體力，也不再移動。

## 執行緒安全與停止機制

- 馬匹位置、剩餘體力與狀態必須使用可見性安全的欄位或同步快照。
- 排名與完賽集合由 `RaceController` 的同步臨界區保護。
- 只有首個完賽執行緒能觸發全場加速事件。
- 背景執行緒不可直接呼叫 Swing 元件；GUI 事件以 `SwingUtilities.invokeLater` 或 Swing `Timer` 進入 EDT。
- 停止賽事時設定停止旗標並 `interrupt` 所有存活的馬匹執行緒。`InterruptedException` 視為正常停止，不顯示錯誤對話框。
- 同一時間只允許一場賽事；比賽中重複按鈕事件會被忽略。

## 錯誤處理

- `JSpinner` 本身限制馬匹數量為 2–10，不接受範圍外值。
- 控制器拒絕零匹、負數或超過 10 匹的程式化呼叫，並拋出有明確訊息的 `IllegalArgumentException`。
- 未預期的背景錯誤會停止該場賽事，將錯誤訊息送到 GUI，並恢復可操作狀態。
- 視窗關閉與執行緒中斷屬於預期生命週期，不當作失敗。

## 驗證策略

純 JDK 測試以 `main` 方法和 Java `assert` 執行，命令使用 `java -ea`。核心隨機來源與時間來源可替換為固定測試值，以便驗證：

- 馬匹數量邊界與無效輸入。
- 多個執行緒幾乎同時完賽時，排名仍無重複且包含所有馬匹。
- 首匹完賽事件只觸發一次。
- 加速倍率正確為 `1.2×`，每秒只消耗一點體力，體力用完後恢復基礎速度。
- 中止賽事後所有馬匹執行緒能結束。
- Swing 元件更新在 EDT 執行。

此外，實際編譯並執行完整賽事，產生開始、比賽中與最終排名三張 Swing 畫面截圖，人工確認跑道、文字、控制元件與名次在 2、5、10 匹時均無重疊或截斷。

## 繳交內容

- `src/`：可直接編譯的 Java 原始碼。
- `test/`：不依賴第三方套件的測試程式。
- `README.md`：編譯、測試與啟動指令。
- `REPORT.md`：繁體中文討論多執行緒與非多執行緒流程的差異，包含反應性、並行性、同步成本、可預測性及適用情境。
- `screenshots/`：開始畫面、比賽進行中與完整排名 GUI 截圖。

## 完成條件

1. 純 JDK 指令可從乾淨的 `out/` 目錄完成編譯。
2. 所有 `java -ea` 測試通過。
3. 每匹馬確實由不同的 Java 執行緒執行。
4. GUI 在比賽期間保持可操作並安全更新。
5. 每場速度與體力重新隨機，排名正確且不重複。
6. 首匹完賽後的自動加速符合體力次數與 20% 倍率規則。
7. 三張 GUI 截圖與討論報告可直接作為作業附件。
