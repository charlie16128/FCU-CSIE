# 依速度變化的馬匹動畫設計

## 目標

讓使用者不只從馬匹的水平位移看出速度差異，也能從跑姿動畫直接辨識快馬、慢馬，以及首匹完賽後的 `+20%` 加速狀態。

## 現況與根因

目前 `Horse` 會依每匹馬的隨機 `baseSpeed` 更新位置，加速時也會把位移倍率設為 `1.20`。但傳給 GUI 的 `HorseSnapshot` 沒有速度資訊，而 `RacePanel.drawHorse` 每次都畫出完全相同的腿、頭與尾巴姿勢。加速狀態只額外顯示光圈、閃電和 `x1.2`，因此馬匹雖然移動速度不同，圖像本身沒有奔跑變化。

## 採用方案

保留現有 Java2D 馬匹，不加入外部圖片資源。使用數個程序化跑姿幀，並以馬匹的實際速度決定幀切換頻率：

- 基礎速度較高的馬，跑姿切換較快。
- 基礎速度較低的馬，跑姿切換較慢。
- `boosting` 為 `true` 時，實際速度與動畫頻率同步提高 20%。
- 加速期間保留現有光圈、閃電和 `x1.2`，讓速度變化同時具備動作與文字提示。
- 等待起跑及已完賽的馬停在固定姿勢，避免畫面在沒有移動時仍持續奔跑。

相較於只有快、慢兩個固定姿勢，這個方案能避免馬匹看起來在跑道上滑行；相較於 GIF 或圖片序列，它不需要額外素材或資源載入邏輯，也能維持目前單一 Java 原始碼即可編譯執行的特性。

## 架構與資料流

### 模型快照

`HorseSnapshot` 新增可供畫面使用的速度資料。快照會提供目前的實際速度；一般狀態等於 `baseSpeed`，加速狀態等於 `baseSpeed * 1.20`，完賽時視為停止。

比賽距離、位置更新、體力消耗、排名同步和每匹馬一條執行緒的架構不變。

### 畫面動畫

`RacePanel` 依以下輸入選擇動畫幀：

1. 目前時間。
2. 馬匹的實際速度。
3. 馬匹是否已完賽。

跑姿至少包含三個循環幀，改變前後腿的伸展方向，並讓尾巴與頭部產生小幅度擺動。幀週期會限制在適合肉眼辨識的範圍內，避免最快的馬出現閃爍，也避免最慢的馬看起來完全靜止。

Swing `Timer` 仍以約 33 毫秒更新快照和觸發重繪，不建立新的動畫執行緒。

### 預覽與完賽

- 尚未開始比賽的預覽馬匹使用固定的中立站姿。
- 比賽中的馬匹依速度循環跑姿。
- 已抵達終點的馬匹停在固定的收腿姿勢。

## 邊界與錯誤處理

- 動畫頻率計算會對速度做上下限限制，避免異常值造成除以零、負週期或過快閃爍。
- 快照保持不可變，背景馬匹執行緒不直接操作 Swing 元件。
- 本次不改變馬匹的隨機速度範圍、加速時長、體力次數或排名規則。

## 驗證

1. 編譯 `HorseRace.java`，確認程式仍只依賴標準 JDK。
2. 以可重現的速度輸入檢查：慢速與快速馬在同一時間點可得到不同動畫幀或不同幀週期；加速後的動畫頻率高於加速前。
3. 啟動 GUI，確認比賽中腿部、尾巴與頭部會變化，快馬的變化較快。
4. 等第一匹馬完賽後，確認其他馬的動作頻率提高，且光圈、閃電和 `x1.2` 仍會顯示。
5. 確認比賽排名、重新開始、馬匹數量切換與視窗關閉行為沒有退化。

## 完成條件

- 使用者能從動作頻率辨識快馬與慢馬。
- 同一匹馬進入 `+20%` 加速後，跑姿動畫明顯加快。
- 等待與完賽狀態不持續播放奔跑動畫。
- 現有多執行緒、GUI 與排名功能維持正常。
