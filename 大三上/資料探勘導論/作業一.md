# 作業一：Candlestick Patterns Discovering

> 用途：本文件作為 Codex 的實作規格。請依本文件完成整個 Python 專案，不要自行改變資料切分、特徵定義、相似度方法、篩選條件與測試原則；若遇到資料來源限制或公式歧義，請先保留原始資料並在輸出中清楚記錄。

---

# 1. 作業背景

本作業目標是從股票歷史 OHLCV（日 K）資料中，將 K 線轉換成數值特徵，利用歷史資料找出具有代表性的「看漲 K 線型態」與「看跌 K 線型態」，再利用相似度比對與回測，篩選出高頻且具有較高預測正確率的 Pattern，最後依獲利表現選出最佳前 10 個看漲與前 10 個看跌 Pattern，並使用 2026 年資料做 out-of-sample 測試。

老師原始要求重點：

- 使用至少 50 檔股票的原始交易量價資料，資料來源可使用 `yfinance`。
- 2018–2025 為歷史資料，2026 為測試資料。
- 將 K 線轉換成數字模型。
- K 線與 K 線之間的關係、漲跌趨勢、成交量都必須被模型化。
- 從歷史資料找出：
  - 三日後收盤價相較當日收盤價上漲超過 5% 的看漲候選型態。
  - 三日後收盤價相較當日收盤價下跌超過 5% 的看跌候選型態。
- 去除除權息等 corporate actions 造成的無效型態。
- 設計 K 線型態的相似度比對方法，並考慮不同特徵權重。
- 將找到的型態放回歷史資料進行二次篩選，保留出現頻率較高、且預測較正確的型態。
- 依獲利情形排序，找出最佳前 10 個看漲與前 10 個看跌 K 線型態。
- 將最佳 Pattern 畫在 GUI 上。
- 使用 2026 測試資料驗證這些 Pattern 是否仍能預測後續行情。
- 至少挑 10 檔不同股票進行 2026 測試與比較。
- 繳交程式碼與報告。

# 4. Corporate Action 與資料清理

老師明確要求去除除權息產生的無效型態。

因此不得直接把「除權息造成的價格跳空」當成真正的 K 線 Pattern。

建議實作方式：

## 4.1 優先方案

使用 Yahoo Finance 的 corporate action 資訊：

- `Dividends`
- `Stock Splits`

當某交易日存在顯著 corporate action 時：

- 該日不可作為 Pattern candidate。
- 該日前後因為特徵計算會引用前一日 / 前 7 日 / 後 3 日資料，建議額外排除鄰近受影響日期。

至少排除：


## 4.2 其他清理

- 日期排序。
- 移除重複日期。
- Open / High / Low / Close / Volume 缺失的列不參與計算。
- 價格 <= 0 的異常資料移除。
- Volume < 0 移除。
- 不使用 forward-fill 補股票價格。
- 計算 rolling 特徵時，資料不足的前幾日直接產生 NaN，最後移除。

# 5. K 線 10 維特徵定義

老師作業定義每一天用 10 個特徵描述。

令：

```text
O = 當日 Open
H = 當日 High
L = 當日 Low
C = 當日 Close
C[t-1] = 前一交易日 Close
V = 當日 Volume
5MV = 當日含在內的 5 日平均成交量
```

## 5.1 當日 K 線三個特徵

### 1. Upper Shadow

```text
upper = (H - max(O, C)) / C * 100
```

### 2. Lower Shadow

```text
lower = (min(O, C) - L) / C * 100
```

### 3. Body

```text
body = (C - O) / C * 100
```

注意：

- `body > 0`：上漲 K。
- `body < 0`：下跌 K。
- 不取絕對值。

## 5.2 前一日 K 線三個特徵

```text
prev_upper = upper[t-1]
prev_lower = lower[t-1]
prev_body  = body[t-1]
```

## 5.3 開盤與收盤型態兩個特徵

### 7. Open Style

```text
open_style = (O - C[t-1]) / C * 100
```

### 8. Close Style

```text
close_style = (C - C[t-1]) / C * 100
```

## 5.4 成交量特徵

### 9. Volume Feature

```text
volume_feature = (V - 5MV) / V
```

若 V = 0，該日不要參與 Pattern 分析。

## 5.5 前五日趨勢

老師投影片公式：

```text
trend = (C[t-2] - C[t-7]) / C[t-7]
```

### 10. Trend

```text
trend = (close.shift(2) - close.shift(7)) / close.shift(7)
```

注意：請完全依上述公式實作，不自行改成 MA slope 或五日報酬率。

# 6. 三日後報酬與候選 Pattern 標記

定義：

```text
return_3d = (C[t+3] - C[t]) / C[t]
```

其中 `t+3` 指的是三個「交易日」後，不是三個日曆日。

候選分類：

```text
return_3d > +0.05
→ Bullish Candidate

return_3d < -0.05
→ Bearish Candidate

其他
→ 不作為 candidate
```

Pattern Discovery 階段只使用：

```text
2018-01-01 ～ 2023-12-31
```

每一筆 candidate 至少保留：

```text
ticker
date
10 feature values
return_3d
direction = bullish / bearish
```

輸出：

```text
data/results/bullish_candidates.csv
data/results/bearish_candidates.csv
```

# 7. 特徵標準化

不同特徵數值尺度不同，不可以直接用原始特徵做 Euclidean Distance。

使用 Z-score：

```text
z_i = (x_i - mean_i) / std_i
```

Scaler 的 mean/std 只能由歷史資料計算。

本專案建議：

- Scaler fit 範圍：2018–2023 的有效特徵資料。
- 2024–2025、2026 只能 transform。

保存 scaler：

```text
models/scaler.pkl
```

或將 mean/std 儲存為 JSON。

# 8. Candidate 聚類成代表 Pattern

不能把所有大漲 / 大跌日期直接當作最終 Pattern，否則會產生大量幾乎一樣的候選。

因此 2018–2023 的候選需要先聚類。

## 8.1 聚類方法

採用階層式聚類（Agglomerative Clustering）或 DBSCAN 二選一。

本專案優先採用：

```text
Agglomerative Clustering
```

理由：

- 不需要隨機初始化。
- 對這種距離式 Pattern 分群較容易解釋。
- 可以直接控制 cluster distance threshold。
- 適合報告呈現。

Bullish candidates 與 Bearish candidates 必須分開聚類。

## 8.2 初始 clustering distance

聚類階段先使用「標準化後、等權重 Euclidean Distance」。

初始 cluster distance threshold 建議：

```text
1.0
```

但不得直接假設它一定最佳。

請實作一個可在 config 中調整的參數：

```text
CLUSTER_DISTANCE_THRESHOLD = 1.0
```

如果最後產生 Pattern 數過少（例如 < 20）或過多（例如 > 300），程式應輸出 warning，方便人工調整。

## 8.3 Pattern centroid

每一個 cluster 的代表 Pattern 使用 centroid：

```text
centroid = 該 cluster 所有 standardized feature vector 的平均值
```

並同時保存原始尺度 centroid（inverse_transform 後）方便 GUI 畫 K 線。

每個 Pattern 保存：

```text
pattern_id
direction
cluster_size
centroid_z[10]
centroid_raw[10]
source candidate dates
```

# 9. Pattern 相似度公式

最終相似度採用「標準化後的加權歐式距離」。

對 Pattern A 與某交易日 B：

```text
D(A, B) = sqrt( Σ w_i * (z_Ai - z_Bi)^2 )
```

其中：

- `z_Ai`：Pattern centroid 第 i 個標準化特徵。
- `z_Bi`：待比對交易日第 i 個標準化特徵。
- `w_i`：第 i 個特徵權重。

距離越小越相似。

當：

```text
D(A, B) <= threshold
```

視為 Pattern 出現。

---

# 10. 權重設計

不要對 10 個特徵各自完全獨立搜尋權重，避免參數過多與 overfitting。

將 10 維分成 5 組：

```text
Group 1: Today Shape
upper, lower, body

Group 2: Previous Shape
prev_upper, prev_lower, prev_body

Group 3: Position
open_style, close_style

Group 4: Volume
volume_feature

Group 5: Trend
trend
```

每組使用同一個 group weight。

候選權重集合：

```text
{0.5, 1.0, 1.5, 2.0}
```

因此一組參數例如：

```text
Today Shape    = 1.5
Previous Shape = 0.5
Position       = 1.0
Volume         = 1.5
Trend          = 2.0
```

映射到 10 維：

```text
[1.5, 1.5, 1.5,
 0.5, 0.5, 0.5,
 1.0, 1.0,
 1.5,
 2.0]
```

完整 Grid Search 最多：

```text
4^5 = 1024 組權重
```

可接受。


# 12. Validation 回測方式

針對每一組：

```text
weights + threshold
```

將 2018–2023 建立出的 Pattern 放到 2024–2025 每一個有效交易日進行比對。

若距離符合 threshold，產生 signal。

## 12.1 Bullish Pattern

若 Pattern 為 bullish：

```text
預測：三個交易日後上漲 > 5%
```

成功條件：

```text
return_3d > +0.05
```

## 12.2 Bearish Pattern

若 Pattern 為 bearish：

```text
預測：三個交易日後下跌 > 5%
```

成功條件：

```text
return_3d < -0.05
```

# 13. 每個 Pattern 的統計指標

每一個 Pattern 至少計算：

```text
occurrence_count
success_count
accuracy
average_return_3d
median_return_3d
std_return_3d
```

其中：

```text
accuracy = success_count / occurrence_count
```

## 13.1 Directional Profit

為了讓 bullish / bearish 都能使用「越大越好」排序：

Bullish：

```text
directional_profit = return_3d
```

Bearish：

```text
directional_profit = -return_3d
```

因此：

- Bullish 上漲 7% → +7%
- Bearish 下跌 7% → +7%

計算：

```text
average_directional_profit
median_directional_profit
```

# 14. Pattern 最低資格篩選

Validation 完成後，Pattern 必須先通過資格篩選，才有資格參加 Top 10 排名。

初始條件採用：

```text
occurrence_count >= 30
accuracy >= 0.60
```

理由：

- 防止只有極少數樣本卻出現很高 accuracy。
- 老師要求型態必須「出現頻率較高」且「預測比較正確」。

如果符合資格的 bullish 或 bearish Pattern 少於 10 個：

依序放寬：

```text
minimum occurrence: 30 → 25 → 20
```

accuracy 原則上維持 60%。

若仍不足 10 個，才允許：

```text
accuracy 60% → 58% → 55%
```

所有放寬行為必須寫入 log 與報告結果，不可默默修改。

---

# 15. 權重與 Threshold 的最佳化目標

不要單純最大化 accuracy，因為容易偏好少量樣本。

對每一組 `weights + threshold`，先取得所有通過最低資格的 Pattern，再計算綜合 Validation Score。

採用以下 score：

```text
pattern_score =
    0.50 * normalized_average_directional_profit
  + 0.30 * normalized_accuracy
  + 0.20 * normalized_log_occurrence
```

其中：

```text
normalized_log_occurrence = normalize(log1p(occurrence_count))
```

Normalization 在同一次 validation 比較集合中使用 min-max normalization。

## 15.1 Parameter Set Score

對某一組 weights + threshold：

1. bullish / bearish 分開。
2. 各取通過資格 Pattern 的前 10 名。
3. 計算 bullish Top 10 pattern_score 平均值。
4. 計算 bearish Top 10 pattern_score 平均值。
5. 最終：

```text
parameter_set_score =
0.5 * mean(top10_bullish_scores)
+ 0.5 * mean(top10_bearish_scores)
```

選擇最高的參數組。

Tie-break 順序：

```text
1. 較高平均 directional profit
2. 較高平均 accuracy
3. 較高總 occurrence
4. 較小 threshold（偏向較嚴格相似度）
```

保存：

```text
models/best_params.json
```

內容至少包含：

```json
{
  "today_shape_weight": 0,
  "previous_shape_weight": 0,
  "position_weight": 0,
  "volume_weight": 0,
  "trend_weight": 0,
  "similarity_threshold": 0,
  "minimum_occurrence": 30,
  "minimum_accuracy": 0.60
}
```

數值由程式實際搜尋後填入。

# 16. Top 10 最終排名方式

在最佳 weights + threshold 已確定後：

重新使用 2024–2025 Validation Data 對所有 Pattern 回測。

先套用：

```text
occurrence >= minimum_occurrence
accuracy >= minimum_accuracy
```

再依：

```text
average_directional_profit
```

由高到低排序。

這符合老師「先找高頻且預測較正確，再依獲利情形排序」的要求。

Bullish / Bearish 必須分開排名。

---

# 17. Top 10 去重

可能發生前 10 名 Pattern 實際上非常接近，因此加入最終去重。

從排名第一名開始依序加入結果：

若新 Pattern 與已選 Pattern 的加權標準化距離：

```text
D < 0.30
```

視為同一類型，不重複加入。

繼續往下找，直到取得：

```text
10 bullish patterns
10 bearish patterns
```

此 `0.30` 為去重 threshold，與 match threshold 是不同用途，不可混用。

若不足 10 個，可將 dedup threshold：

```text
0.30 → 0.25 → 0.20
```

並記錄 log。

輸出：

```text
data/results/top10_bullish.csv
data/results/top10_bearish.csv
models/final_patterns.json
```

2026 測試前必須鎖定以下全部內容：

```text
Minimum accuracy
```

# 19. 2026 Final Test

從台灣 50 的 50 檔股票中，至少選 10 檔進行最終測試。

建議為避免 cherry-picking：

## 方案

固定選取市值具代表性的 10 檔，而不是看完 2026 結果再挑。

將實際 10 檔代碼寫入：

```text
config/test_tickers.txt
```

並在跑 2026 前固定。

## 19.1 每日測試流程

對每一檔測試股票、每一個 2026 有效交易日：

```text
1. 計算 10 維特徵
2. 使用舊 scaler 做 z-score transform
3. 與 10 bullish + 10 bearish Pattern 計算 weighted distance
4. 若 D <= final threshold，視為 signal
5. 三個交易日後計算實際 return_3d
6. 判斷是否預測成功
```

如果同一天匹配多個同方向 Pattern：

- 每個 Pattern 的命中統計分開計算。
- 股票交易層級的 signal 可只算一次，避免重複下單。

如果同一天同時匹配 bullish 與 bearish：

- 標記為 `conflict_signal = True`。
- 不納入模擬交易績效。
- 仍保留 Pattern 個別命中統計。

# 21. 額外投資模擬（建議實作）

老師要求討論是否能幫助投資人獲利，因此除了「三日後是否超過 ±5%」之外，增加簡單策略模擬。

## Bullish signal

```text
Close[t] 買入
Close[t+3] 賣出
profit = (Close[t+3] - Close[t]) / Close[t]
```

## Bearish signal

若不假設台股實際放空限制，可只做理論 short return：

```text
profit = (Close[t] - Close[t+3]) / Close[t]
```

報告必須註明：

- 尚未考慮交易成本。
- 尚未考慮滑價。
- bearish 為理論放空報酬。
- 不代表實際可直接獲利。

可額外與 Buy & Hold 做比較，但不要用 Buy & Hold 決定 Pattern。

- 建立可安全用於 Pattern 分析的資料。

## `build_features.py`

- 依老師公式產生完整 10 維特徵。
- 計算 `return_3d`。
- 不做未來資料洩漏。

## `find_candidates.py`

- 只使用 2018–2023。
- 抽取 bullish / bearish candidates。

## `cluster_patterns.py`

- 對 candidate 的 standardized features 聚類。
- bullish / bearish 分開。
- 計算 centroid。

## `similarity.py`

提供純函數：

```text
weighted_distance(vector_a, vector_b, weights)
is_match(distance, threshold)
```

## `optimize_similarity.py`

- 使用 2024–2025。
- Grid Search 5 組 weights + threshold。
- 計算 parameter_set_score。
- 找 best params。

## `backtest_patterns.py`

- 對指定 Pattern / weights / threshold 做 validation 或 test。
- 輸出 pattern-level metrics。

## `select_top10.py`

- minimum occurrence / accuracy 過濾。
- 依 average directional profit 排序。
- 去重。
- 取得 10 bullish + 10 bearish。

## `test_2026.py`

- 僅使用鎖定參數。
- 對固定至少 10 檔股票跑 2026 final test。

## `visualization.py`

- 畫代表 Pattern K 線圖。
- 畫 performance chart。
- 輸出報告需要的 PNG。

## `gui.py`

- 顯示 Top 10 bullish / bearish Pattern。
- 點擊 Pattern 顯示：
  - 代表 K 線。
  - 10 維特徵。
  - Validation occurrence。
  - Validation accuracy。
  - Validation avg profit。
  - 2026 test result。

# 29. 防止 Data Leakage 的硬性規則

Codex 實作時必須遵守：

1. 2026 不可以參與 scaler fit。
2. 2026 不可以參與 clustering。
3. 2026 不可以參與 weight search。
4. 2026 不可以參與 threshold search。
5. 2026 不可以參與 minimum occurrence / accuracy 調整。
6. 2026 不可以參與 Top 10 選擇。
7. `return_3d` 只能當 label / 評估結果，不得放入特徵。
8. 計算某日特徵時，只能使用當日與過去資料。
9. 任何 rolling average 都不能引用未來資料。

# 35. Codex 實作原則

Codex 在實作本專案時請遵循：

1. 先建立專案骨架。
2. 每完成一個 phase 就執行測試。
3. 不要一開始直接寫 GUI。
4. 所有公式集中管理，避免同一公式在不同檔案重複實作。
5. 所有重要參數放 `config/settings.yaml`。
6. 不能把最佳參數 hard-code 成預期結果；必須真的從 2024–2025 搜尋。
7. 程式要能重新執行且得到一致結果。
8. 若 clustering 使用任何隨機演算法，設定固定 random seed；目前優先 Agglomerative，因此不需 random seed。
9. 所有 CSV 使用 UTF-8。
10. 所有日期統一使用 `YYYY-MM-DD`。
11. 所有百分比計算內部使用 decimal，顯示時才轉百分比。
12. 發生單一股票資料錯誤時不要讓整個 50 檔流程中斷，記錄 error 後繼續。
13. 不允許 2026 資料影響模型選擇。
